## 二、为什么 certbot 装在 venv 里

Alibaba Cloud Linux 4 上没有现成路径，依次尝试：

1. `dnf install certbot` → **No matching Packages**（源里没有）
2. `dnf install epel-release` → **No match**（alinux 源不含 EPEL）
3. 直连 Fedora 的 `epel-release-latest-9.noarch.rpm` → **下载中断**（2.8 kB/s，被限速）
4. 清华 pypi 镜像 → **403**（拒绝了该请求）
5. **阿里云 pypi 镜像 → 成功**

最终方案：

```bash
python3 -m venv /opt/certbot
/opt/certbot/bin/pip install --upgrade pip \
  -i https://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
/opt/certbot/bin/pip install certbot \
  -i https://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
ln -sf /opt/certbot/bin/certbot /usr/local/bin/certbot
```

> **教训**：这台服务器上装 Python 包只用阿里云源，清华源 403、EPEL 直连超时。

## 三、nginx 配置拆成三个文件

放在项目 `deploy/` 下，部署时分别拷到 `/etc/nginx/conf.d/`。

| 文件 | 部署位置 | 作用 |
|---|---|---|
| `nginx.conf` | `ycwl-chat.conf` | **生产配置**：80 跳转 + 443 主站 + IP 直连块 |
| `nginx-bootstrap.conf` | 同上（引导期） | **首次部署用**：仅 HTTP + ACME 校验路径 |
| `nginx-gzip.conf` | `gzip.conf` | gzip 压缩（http 上下文） |

**为什么要 bootstrap**：`nginx.conf` 的 443 块引用了证书文件，证书不存在时 `nginx -t` 直接失败、整个部署中断。所以首次部署必须先起 HTTP 引导版 → 签发证书 → 再换正式配置。这个分支逻辑已写进 `post-install.sh`。

三个 server 块的分工：

```
server 80   server_name 47.242.248.104 _    → IP 直连业务（不跳转，便于排查）
server 80   server_name ycwl.chat           → ACME 校验 + 301 跳 HTTPS
server 443  server_name ycwl.chat           → HTTPS 主站
```

ACME 校验路径用 `location ^~ /.well-known/acme-challenge/`，`^~` 保证它优先于 `location /` 的 301 跳转 —— 否则续期时会被跳走导致校验失败。

## 四、续期机制

`deploy/certbot-renew.service` + `.timer`：

```ini
ExecStart=/opt/certbot/bin/certbot renew --quiet --deploy-hook "systemctl reload nginx"
OnCalendar=*-*-* 00,12:17:00
RandomizedDelaySec=3600
```

- 用 **webroot 模式**（`/var/www/certbot`），不依赖 certbot-nginx 插件 —— 少一个依赖，且不会让 certbot 自动改写 nginx 配置
- `--deploy-hook` 在**真正续期成功后**才 reload nginx（平时续期检查是空操作）
- 距到期 30 天内才会真正续期

验证命令：

```bash
certbot renew --dry-run                              # 演练，不消耗签发额度
systemctl list-timers certbot-renew.timer            # 看下次执行时间
openssl x509 -in /etc/letsencrypt/live/ycwl.chat/fullchain.pem -noout -dates
```

**已演练通过**：`Congratulations, all simulated renewals succeeded.`

## 六、安全头

```
Strict-Transport-Security: max-age=31536000      （新增，暂不含 includeSubDomains/preload）
X-Frame-Options: SAMEORIGIN
X-Content-Type-Options: nosniff
X-XSS-Protection: 1; mode=block
Referrer-Policy: strict-origin-when-cross-origin
```

HSTS 故意不加 `includeSubDomains` 和 `preload` —— 一旦加错，回退到 HTTP 会非常痛苦，首次上线先保守。

## 八、排查手册

| 现象 | 原因 | 处理 |
|---|---|---|
| `duplicate upstream "mqs_api"` | `/etc/nginx/conf.d/` 下有多份配置都定义了 upstream | `ls /etc/nginx/conf.d/`，移走历史文件（如旧的 `wycl-chat.conf`） |
| `nginx -t` 报证书文件不存在 | 证书未签发就用正式配置 | 先上 `nginx-bootstrap.conf`，签发后再换 |
| 签发失败 | 域名未解析 / 80 端口不通 | `getent hosts ycwl.chat` 确认解析；确认安全组放行 80 |
| HTTPS 打开但证书告警 | 证书不含该域名 | `openssl x509 -noout -text \| grep DNS:` 看 SAN |
| 续期失败 | ACME 路径被 301 跳走 | 确认 `location ^~ /.well-known/acme-challenge/` 存在 |
