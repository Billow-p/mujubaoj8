# 信息架构与板块划分方案

> 2026-09-10 · 待确认后实施
> 起因：用户反馈「板块逻辑不清楚，新建报价单和配置中心的区别是什么？又有一个材料中心，没有层层递进的感觉」

---

## 一、问题诊断

### 现在的导航

```
工作台 | 新建报价单 | 客户库 | 配置中心 | 材料中心 | 报价项中心 | 后台管理
```

7 项平级排列。问题不在数量，**在维度混乱** —— 这 7 项其实属于 3 个不同层次，却被拉平了：

| 导航项 | 实际性质 | 问题 |
|---|---|---|
| 工作台 | 业务：报价单列表 | — |
| **新建报价单** | **一个动作**，不是板块 | 和「工作台」其实是同一件事的两面 |
| 客户库 | 业务：主数据 | — |
| 配置中心 | 设置：定义"怎么算钱" | 与下面两项是同一类 |
| 材料中心 | 设置：材料与价格 | 属于配置，却独立成项 |
| **报价项中心** | 设置：**已被配置中心完全覆盖** | 遗留项，功能重复 |
| 后台管理 | 管理：用户与数据 | 只有管理员看得到，性质和上面都不同 |

### 四个具体病症

**1. 动作当板块。**
"新建报价单"是个动作 —— 主流做法（Salesforce、金蝶、用友）都是把它放在列表页右上角，不占导航位。现在它和"工作台"平级，用户自然会问"这俩什么区别"。

**2. 同类被拆散。**
配置中心、材料中心、报价项中心本质都是"配置" —— 一年改几次的东西，却和每天用的工作台平级。用户要在三个平级入口之间跳，还得记住哪个功能在哪。

**3. 层次没有表达。**
日常（每天用）→ 配置（建站时设一次）→ 管理（极少用）是三档频率，现在完全看不出。

**4. 有重复项。**
"报价项中心"的功能已被配置中心覆盖（上轮已下线"参数中心"，报价项中心是同一类遗留）。

---

## 二、方案：三层信息架构

### 原则

> **按「用户要做什么」分，不按「数据是什么」分。**

这也是主流 SaaS / ERP 的通用做法：业务功能放主导航，配置收进"设置"，管理收进"设置"里的管理员专区。

### 建议的导航

```
报价单          业务 · 每天用    列表 + 右上角「新建报价单」
客户            业务 · 经常用    客户列表 → 客户详情 → 历史报价
设置 ⚙          配置 · 偶尔用    进入后左侧二级导航
  ├─ 报价配置                     原「配置中心」
  ├─ 材料库                       原材料中心（全局材料 + 价格历史）
  ├─ 商务条款                     条款模板（从配置中心抽出）
  └─ 团队与数据                   原「后台管理」，仅管理员可见
```

### 为什么是这三个

| 入口 | 用户的心理问题 | 频率 |
|---|---|---|
| 报价单 | "我要报价 / 我要找那张单" | 每天 |
| 客户 | "这个客户之前报过什么" | 经常 |
| 设置 | "算法/价格要调一下" | 建站一次，偶尔调整 |

**"新建报价单"不再是导航项** —— 它是报价单列表页右上角的一个按钮。这一条直接消除了你提的那个困惑。

## 三、每个板块的功能定义

### ① 报价单（默认落地页）

| 区域 | 功能 |
|---|---|
| 列表 | 全部报价单：编号、客户、产品、金额、状态、时间；支持按状态/客户/时间筛选 |
| 右上角 | **+ 新建报价单**（选模具类型 → 填数据 → 自动出价 → 生成 → 可选发客户邮箱 / 导出 Excel） |
| 行内操作 | 查看详情、导出 Excel、发送邮件、复制为新报价、状态流转 |
| 空态引导 | 若还没配过模具类型 → 显示"① 先去配置模具类型 ② 再回来报价"的两步引导（**层层递进的入口**） |

### ② 客户

| 区域 | 功能 |
|---|---|
| 列表 | 客户名、联系人、电话、报价单数、最近报价金额 |
| 详情 | 客户资料 + 该客户全部历史报价（可点进任意一单） |
| 自动联动 | 新建报价时自动入库/复用，不用先建客户 |

### ③ 设置 → 报价配置（原配置中心）

这是系统的核心 —— **定义"钱怎么算"**。

| 区域 | 功能 |
|---|---|
| 模具类型 | 注塑 / 压铸 / 双色…可增删改；每种类型一套独立配置 |
| ① 参数 | 报价时要填的数据项（腔数、单件重量、模具尺寸…）；类型可选"数字 / 下拉" |
| ② 费用项与公式 | 要收哪些费用、用哪种计算方式（固定金额 / 数量×单价 / 按尺寸 / 工时 / 重量 / 比例 / 手填 / 高级公式）；可勾选"按件计价" |
| ③ 材料 | 本类型**可选用**的材料（引用全局材料库，不复制） |
| ④ 条款 | 本类型的商务条款（默认引用条款模板，可覆盖） |
| 实时算价 | 右栏实时试算，改什么都立刻看到价格 |
| 保存门禁 | 公式算不出来不允许启用（原有能力保留） |

**建议加：配置步骤条** —— 参数 → 费用项 → 材料 → 条款 → 试算，让"配一个模具类型"有清晰的推进感。

### ④ 设置 → 材料库（原材料中心）

| 区域 | 功能 |
|---|---|
| 分类浏览 | 按用途分四类（模具钢材 / 塑料原料 / 压铸合金 / 辅助材料），每类再按材质细分；分组折叠 |
| 改价 | 改单价自动生成价格版本，可查历史 |
| 预置材料 | 35 种行业参考材料，一键导入；已存在的不覆盖用户改过的价格 |
| 定位 | **全局材料库，所有模具类型共用一份价格** |

### ⑤ 设置 → 商务条款

| 区域 | 功能 |
|---|---|
| 条款模板 | 全局默认条款（税费、运费、交期、付款、质保…） |
| 覆盖 | 单个模具类型可覆盖模板内容 |

> 目前条款是每个模具类型各存一套。抽出全局模板可以减少重复维护。

### ⑥ 设置 → 团队与数据（原后台管理，仅管理员）

| 区域 | 功能 |
|---|---|
| 数据概览 | 用户数、客户数、报价单数、近 30 天新增、累计与已成交金额 |
| 状态分布 | 草稿 / 已发送 / 已成交 / 已作废 各多少 |
| 用户列表 | 邮箱、姓名、角色、邮箱验证、注册时间、最后登录 + 每人报价单数与金额 |

## 四、需要你拍板的 5 个点

### 1. 「新建报价单」从导航移除，改成列表页按钮？

**建议：是。** 这是消除困惑最直接的一步。
（若你希望它保留为快捷入口，也可以放在导航最右侧、和设置之间。）

### 2. 「报价项中心」直接删掉？

**建议：删。** 配置中心已完全覆盖（上轮删了参数中心，报价项中心是同一类遗留）。

### 3. 材料和配置中心的关系怎么定？

现状是**两套材料**：材料中心一份（全局），配置中心每个模具类型各复制一份 —— 同一个 ABS 有两个价格，改价要改两次。

| 选项 | 说明 |
|---|---|
| **A. 全局材料 + 引用（推荐）** | 材料只有一份，所有模具类型共用。配置中心的"材料"变成**勾选本类型用哪些**，改价统一去材料库 |
| B. 维持两套 | 各类型独立定价，互不影响；但同一个材料要改多处，容易出现价格不一致 |

**建议 A。** 你的业务里材料价格是采购价，全公司一个价才合理。

### 4. 两个数量参数合并？

现在注塑类型有「首单数量」（300000，老模型遗留）和「注塑数量」（5000，按件计价用）两个，容易混。

**建议：只保留一个，统一叫「订单数量」**（本次要生产多少件），删掉冗余的那个。
（各类型可显示成"注塑数量 / 压铸数量"，语义相同。）

### 5. 条款是否抽出全局模板？

**建议：抽。** 条款内容（税费、付款方式）通常全公司一致，没必要每种模具类型各维护一套。

## 五、实施顺序（确认后执行）

| 步 | 内容 | 影响面 |
|---|---|---|
| 1 | 导航改三层 + 设置页壳（二级导航） | 前端导航、路由 |
| 2 | 报价单列表加"新建"按钮；移除导航项 | 前端 |
| 3 | 删除报价项中心 | 前端 + 后端路由 |
| 4 | 材料改为全局引用（决策 3 选 A 时） | 数据模型 + 配置中心逻辑，**需要数据迁移** |
| 5 | 合并数量参数（决策 4） | 预置模板 + 已有配置 |
| 6 | 条款抽全局模板（决策 5） | 数据模型 + 配置中心 |
| 7 | 空态引导 + 配置步骤条 | 前端 |

**注意**：第 4、5、6 项涉及**已有数据的迁移**，我会先把迁移脚本写好并在本地验证，确认无误再上服务器，且部署前先 `pg_dump` 备份。

第 1、2、3、7 项是纯前端，改动小、风险低，可以优先做。

## 六、这个方案解决了什么

| 你提的问题 | 解决方案 |
|---|---|
| 不清楚新建报价单和配置中心的区别 | 新建报价单降级为按钮，不再是并列板块 |
| 又有一个材料中心 | 材料库收进"设置"，与报价配置同层；并统一为一套材料（决策 3） |
| 没有层层递进 | 三层结构（业务 / 设置 / 管理）+ 空态引导 + 配置步骤条 |
| 两个数量参数 | 合并为一个订单数量（决策 4） |
| 板块太多 | 7 项 → 3 项主导航（设置内 4 个二级项） |
